## Incoming and rally follow-up — 0.10.96

@task-VHE-F8X6B6 audits the remaining getIncomingMarches:march and getRallyById:rally sources. Quiet Smart gathering previously polled incoming every >15 seconds, including every unrelated RPC after expiry; it now uses 60 seconds when no live attacks remain, 15 seconds while attacks are active, and reuses full native snapshots plus passive deltas. Initial hydration still requires snapshotAt; a lone push cannot prove no other attacks exist. Mine gather/return notifications no longer request incoming because the reducer handles their captured termination information. Hospital/attack timing and the final-ten-second defensive recall remain unchanged.

world-read.plan coordinates optional automatic incoming/rally reads per account and rally/map, persists bounded state (200 entries), and serializes state writes. Incoming in-flight reads coalesce for ten seconds. Rally push bursts coalesce for five seconds; newer versions or later unversioned invalidations record one trailing refresh through hwa-world-read. A native getRallyById response records account-scoped rallyReadStatus timestamps/map/version and can satisfy that trailing refresh without sending another RPC. Stale, wrong-map, old-version or foreign-account details cannot satisfy it. Pending refreshes survive worker restart; account changes, disabled RPC or loss of the game tab discard them. Missing replies never start an infinite automatic retry loop. Alarm timing is best effort; decision-critical reads bypass the debounce.

The explicit Smart reservation recheck after troop return and existing Raid Queue reads for member counts before auto-cancel are deliberately preserved. They consume current server results for join/cancel decisions, so optional push coalescing does not delay their deadlines. Explicit user refresh also bypasses coordination.
